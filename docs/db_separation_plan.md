# 微信数据库功能分离设计方案 (DB Separation Plan)

> **文档目的**: 记录关于将微信数据库解密与读取功能从主下载器中剥离的设计思路、优势分析及实施计划，作为后续开发与维护的参考依据。
> **创建日期**: 2026-02-08

---

## 1. 背景与现状

目前的 `get_wx_gzh.py` (主程序) 集成了两类性质截然不同的功能：
1.  **文章下载 (Downloader)**: 负责网络请求、HTML 解析、资源本地化、PDF 生成等 (I/O 密集型)。
2.  **数据提取 (Extractor)**: 负责微信 `Favorite.db` 的解密 (SQLCipher) 和结构解析 (CPU/本地文件操作)。

**存在的问题**:
*   **职责不清**: 主程序参数过于庞杂，既有 `--concurrency` (网络并发)，又有 `--key` (解密密钥)，用户体验割裂。
*   **代码耦合**: `core/app.py` 中包含了数据库检测逻辑和依赖检查 (`sqlcipher`)，即使用户只处理文本链接也不得不背负这些逻辑。
*   **安全隐患**: 数据库解密模块 (`db_decrypter.py`) 存在潜在的 SQL 注入风险（虽已加固），且长期作为“死代码”存在于主代码库中，增加了维护成本。
*   **流程僵化**: 用户难以在解密后和下载前对 URL 列表进行人工筛选或预处理。

---

## 2. 重构目标：分离设计

我们将系统拆分为两个独立的工具，各司其职，通过“文件”进行协作。

### 2.1 新工具：`wechat_db_tool.py` (数据提取器)
*   **定位**: 专注于从微信本地数据库中提取资产链接。
*   **核心功能**:
    *   **解密**: 接收加密数据库 (`.db`) 和密钥 (`key`)，调用 `core.db_decrypter` 生成明文数据库。
    *   **解析**: 读取明文数据库 (`core.db_parser`)，提取公众号文章链接。
    *   **导出**: 将链接保存为标准的 `urls.txt` 格式文件。
*   **依赖**: 仅该工具依赖 `sqlcipher`。

### 2.2 主程序：`get_wx_gzh.py` (纯粹下载器)
*   **定位**: 专注于将 URL 转化为本地资产。
*   **变更**:
    *   **移除**: 删除所有数据库相关参数 (`--db`, `--key`, `--db-path`, `--decrypted-db`)。
    *   **简化**: 移除 `core/app.py` 中的数据库分支逻辑和 `sqlcipher` 环境检查。
    *   **输入**: 仅接受 URL 字符串或包含 URL 的文本文件。

---

## 3. 新工作流 (Workflow)

采用 **管道式 (Pipeline)** 工作流：

1.  **提取阶段**: 用户使用 `wechat_db_tool.py` 从数据库提取链接。
    ```bash
    python wechat_db_tool.py --db-path input/Favorite.db --key "xxxxx" -o input/db_urls.txt
    ```

2.  **中间阶段 (可选)**: 用户可以打开 `input/db_urls.txt`，手动删除不需要下载的链接，或合并其他来源的链接。

3.  **下载阶段**: 用户将清洗后的列表传给主程序。
    ```bash
    python get_wx_gzh.py input/db_urls.txt
    ```

---

## 4. 优势分析

| 维度 | 优势说明 |
| :--- | :--- |
| **单一职责 (SRP)** | 下载器不再关心数据库结构，提取器不再关心网络请求。逻辑解耦，互不干扰。 |
| **安全性 (Security)** | SQL 注入风险被物理隔离在 `wechat_db_tool.py` 中。普通下载用户无需承担该风险组件。 |
| **可维护性** | 若微信数据库格式更新，仅需升级 `db_tool`，下载器核心逻辑无需变动。 |
| **用户体验** | CLI 参数更清晰。不需要数据库功能的用户不会被相关参数困扰，也不会收到缺失 `sqlcipher` 的报错。 |
| **灵活性** | 导出的 URL 列表成为了通用的中间格式，方便对接其他工具或脚本。 |

---

## 5. 实施路线图

1.  **创建独立工具**: 开发 `wechat_db_tool.py`，复用并整合 `core/db_decrypter.py` 和 `core/db_parser.py` 的逻辑。
2.  **验证**: 确保新工具能正确解密并导出 URL 列表。
3.  **清理主程序**: 从 `get_wx_gzh.py` 和 `core/app.py` 中彻底移除数据库相关代码与参数。
4.  **文档更新**: 更新 `README.md`，介绍新的两步走操作流程。
